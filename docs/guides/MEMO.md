# 长期备忘录与批量补记

## 启用

需要 Node.js 24.14 或经测试兼容的更新版本（使用内置 `node:sqlite`；该版本会输出实验功能提示）。配置示例默认关闭；在本机 `config.json` 增加以下字段并重启桥接：

```json
{ "memo": { "enabled": true } }
```

数据库自动保存在仓库 `state/memo/memos.sqlite3`。不要将config、state、导出或备份提交到Git。关闭开关并重启可停用功能，已保存数据不会自动删除。

## 常用命令

群聊先真实艾特机器人；主人私聊直接发：

```text
帮我记住：每周整理读书笔记
记一下 2026-03-04 11:10 参加小组例会
备忘 搜索 读书
备忘 列表 2
备忘 查看 M-000001
备忘 修改 M-000001 新正文
备忘 删除 M-000001
备忘 确认删除 M-000001
备忘 导出 1
```

编号以保存回执为准。删除须在5分钟内确认；条目中途修改则旧确认失效。导出为分页JSON文本，每页一条，不是附件发送。

## 批量补记

```text
补记一下
1月5日：整理书单
2月6日：检查文档
2月6日：安排小组例会
2月6日 20:43：1200字摘要，页码 20–30
```

按明确日期和可选时间分段，不要求短横线；支持换行、分号或同行连续日期。省略年份固定按2026年，这是当前协议约定，不随服务器年份自动变化；可写明年份。只给日期就只展示日期，不展示虚构的零点时分；给时间按北京时间解析，可带秒。无法明确归属、日期非法或正文明显截断时整批拒绝，不猜测补全。

整批一个事务，每条独立编号，同一天多条不合并；重复处理同一QQ来源消息不会重复插入。每批最多50条、50000字符，每条最多10000字符，每会话最多5000条有效记录。

## 权限与时间语义

- 仅主人私聊可访问个人备忘；白名单群内全员可新增、查询本群备忘。
- 创建者本人或主人可修改/删除；昵称或群管理员头衔不授予额外权限。各群与主人私聊隔离。
- 作者由QQ真实消息事件确定，不允许模型自由填写作者进行写入。
- `qq_memo` 和 `/api/socialV2/memo` 仅提供search/list/get；强制会话令牌，MCP继承SELF_KEY校验。
- 根据相关话题召回少量备忘，内容作为数据而非指令；本地片段检索不保证同义语义检索。
- `created/updated` 为真实入库/修改时间；`recorded` 为指定记录时间，`record_precision` 区分date/second。旧记录回退到created，增量迁移不改写原时间。
- 指定时间条目另列实际入库时间；修改正文不改变原指定时间。记事不自动创建提醒或执行正文描述的操作。

## 备份与恢复

```bash
python3 scripts/backup-memo.py
# 或指定另一份仓库根目录：
python3 scripts/backup-memo.py --root /path/to/qq-bridge
```

脚本使用SQLite一致性备份，检查完整性，保留最近7个日备份及周一生成的4个周备份，并输出受保护的全库JSON。备份在 `state/memo/backups/`，运维导出在 `state/memo/exports/`。全库导出包含各会话数据，不应发给单个群。

可按自己的运行环境用systemd timer每天北京时间04:15调度，设置UMask=0077；本提交不自动安装系统服务。备份与数据库属于敏感运行数据，不加入版本控制。

删除是软删除：正常查询和召回立即不可见，修订历史、操作回执及历史备份可能保留原文；修订历史尚无自动清理。不要将普通删除解释为彻底擦除。

恢复前停止桥接、保留当前库，使用SQLite一致性备份接口恢复到新库并检查完整性，再替换并正确处理旧WAL/SHM，最后重启验收。不要在运行中只覆盖主数据库文件。
