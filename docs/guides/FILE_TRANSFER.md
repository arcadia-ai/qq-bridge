# 群图片与文件交付 V1

## 使用
- 白名单群真实 @机器人：`找一张 Linux logo 发群`，或 `找一下 Firefox 安装包，Windows x64，下载后发群`。
- 安装包缺系统/架构时先询问；安卓不要求桌面架构。只下载交付，绝不安装或执行。
- 模型先用既有 Tavily 找官网/官方 Release，取公开文件直链，调用 `qq_fetch_and_send`。
- `sourceMessageId` 必须是真实入站消息 ID，不是 seq；补充平台可以引用同人的 @回复。
- `queued` 仅代表排队。后台完成才自动交付；`qq_transfer_status` 查询本群任务状态。
- 每条来源只交付一个资源，不跨群、不接收本机路径、Cookie 或任意请求头。

## 开关与限制
`config.json` 的 `fileTransfer`（示例见 config.example.json）默认关闭；开启/关闭后重启桥接及 DSH，刷新 MCP 工具。
默认文件 500,000,000 字节、图片 20,000,000 字节；缓存 2 GB、保留 24 小时；单群同时一个任务、全局单 worker。
每人每小时 3 次、每群每小时 8 次。失败也计次。限额不是 QQ 平台发送能力承诺。

## 安全与状态
- 真实入站事件独立保存在内存，15 分钟有效，要求真实 @、同作者；转发/角色名/模型文字不作授权。
- 当前会话精确令牌、白名单、暂停/静默和同作者取消状态，在接收及发送前检查。
- 公网 HTTP(S) 普通端口；安装包 HTTPS。逐跳 DNS 安全校验并固定 IP，禁止私网和 HTTPS 降级。
- 流式限额/超时、文件头与扩展名、HTML 登录页识别、SHA-256；有可靠期望校验值才比较，不编造签名。
- 文件缓存只读挂载给 QQ，目录 2750、文件 0640，无执行位。
- SQLite 先记录 sending 再外发，重启不自动重传。发送超时标记 send_unknown；上传有 file_id 但无聊天回读证据，标记 uploaded_unverified。
- SnowLuma v2.0.0 群文件发布失败可能仍返回 file_id，因此不能仅据 file_id 声称已发群。
- 文件头检查不等于病毒扫描，官方来源判别依赖搜索与模型，首版未提供沙箱或杀毒保证。

## 本机部署
- 任务账本：`state/transfers/jobs.sqlite3`（含 URL，私密，不提交）。
- 缓存：项目外 `../transfers/out`，须同路径只读挂载至 SnowLuma，并允许 QQ 的实际 GID 1000 读取。
- 不升级已带兼容补丁的 SDK，不引入独立服务。
- 测试：`node --test scripts/test-transfers.mjs`，全为离线 fixture，不会真实发送 QQ。

## 验收边界
管理员明确批准后，独立运维测试账本可以验证真实下载→共享目录→QQ 图片/文件回读。
该测试不伪造桥接入站消息、不开放生产授权旁路；日常 @→搜索→排队的完整模型入口需要群内真实请求另行验收。
